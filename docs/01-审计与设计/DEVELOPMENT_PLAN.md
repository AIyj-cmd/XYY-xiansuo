# XYY-xiansuo 后续开发计划

> 修订日期：2026-07-30
> 当前状态：需求审计与技术设计修订
> 重要：本计划只描述以后如何开发，本次不执行任何开发、测试、迁移或接入

## 1. 目标和范围

后续开发目标：

- 重要业务事件通过普通微信触达；
- 普通微信不可用时可降级到企业微信；
- DeepSeek 提供只读沟通总结、跟进建议和报告文字总结；
- 原线索系统始终是唯一事实源；
- 外围服务失败不影响主业务；
- 通知低噪声、可配置、可审计、可回滚。

第一阶段不包含：

- 普通新增线索通知；
- 普通编辑、标签、收藏和备忘通知；
- 新五级销售阶段或相关迁移；
- AI 客户价值评分、A/B/C 分类、成交概率；
- AI 写操作；
- 企业微信作为唯一正式渠道；
- 强制上线长期无活动 24/48/72 小时提醒；
- 未经 PoC 的普通微信生产接入。

全计划统一事件名为 `owner_changed`、`scheduled_follow_overdue`、`visit_reminder`、`status_changed`、`daily_report`、`weekly_report`；`inactive_lead` 独立、默认关闭。不存在普通新增线索事件。

1. 业务口径确认；
2. 普通微信机器人候选调研；

4. 当前安全和数据库基线修复；
5. 数据库迁移机制；
6. AI 和新模块权限边界；
7. 通知队列、规则、幂等和 dry-run；
8. 接入通过 PoC 的微信渠道；
9. 负责人变更提醒试点；
10. 拜访计划和提醒；
11. 约定跟进逾期提醒；

13. 确定性日报；
14. DeepSeek 客户总结和跟进建议；

前一阶段的退出条件未满足，不进入依赖它的后续阶段。

## 5. 阶段 3：普通微信独立 PoC

### 5.1 隔离要求

- 不连接生产数据库；
- 不读取真实客户资料；
- 不使用老板主微信或销售主账号；
- 使用虚构客户和固定测试消息；
- 单独机器/容器/账号；
- 不向 PoC 提供 JWT_SECRET、管理员账号、DeepSeek Key 或生产 URL；
- 不把 OpenClaw 的 Shell、文件、数据库或管理工具暴露给微信；
- 所有 PoC 凭证可随时吊销。

### 5.2 PoC A：iLink 普通微信 Bot

优先验证腾讯官方 `openclaw-weixin` 所代表的 iLink 能力：

- 普通微信用户能否稳定找到/使用 Bot；
- 扫码授权和凭证恢复；
- 主动发送是否必须先收到用户消息；
- `context_token` 的作用和有效期；
- 刚互动、超过 24 小时、session 过期时的行为；
- 发送文本、链接、图片/卡片的真实能力；
- 接收文本；
- 群聊是否支持；
- 服务重启、网络中断和重新扫码；
- 失败码和重复投递。

可以使用 OpeniLink Hub 或窄化 Node SDK做接入验证，但要单独记录其社区实现、许可和未获官方授权风险。PoC 不能因为某 SDK 返回 200 就判定用户端一定收到。

### 5.3 PoC B：Windows UIAutomation

仅在 iLink 不能满足定时主动通知时评估：

- WeChatAuto.SDK；
- pyweixin。

使用专用 Windows 机器和专用测试微信。不得把 Hook/注入项目作为默认替代。

### 5.4 最低验证清单

- 稳定登录；
- 长期在线；
- 主动给指定联系人发送；
- 接收指定联系人消息；
- 文本、链接或卡片；
- 断线恢复；
- 进程和机器重启恢复；
- 客户端升级兼容；
- 同账号多设备影响；
- 消息频率限制；
- 风控/封号风险；
- HTTP API 或 Webhook；
- Docker/Linux 或 Windows 专机要求；
- 连续运行 3 至 7 天；
- 是否每次/定期人工扫码；
- 付费组件/VIP/puppet；
- 日志是否泄露隐私和 token。

### 5.5 退出条件

- 有完整运行记录和失败样本；
- 明确“主动通知”窗口，不用猜测；
- 明确恢复成本和封号风险；
- 普通微信 adapter 候选通过业务/技术/安全评审；
- 如未通过，明确选择企业微信降级，而不是强行上线。

## 6. 阶段 4：安全和数据库基线修复

该阶段只在获得下一阶段开发授权后执行。

### 6.1 版本与部署事实

- 核验生产实际 commit；
- 区分当前未提交工作区修复和线上代码；
- 提交、评审、测试并发布必要基线；
- 记录数据库真实路径和备份位置。

### 6.2 JWT 角色刷新

- JWT 只提供身份 id；
- 每次请求从数据库读取 id、username、name、role、is_active；
- 角色降级立即生效；
- 停用立即生效；
- 测试旧管理员 token 被降级后的 `requireAdmin`。

### 6.3 默认管理员

- 移除已提交版本的固定 `admin / xyy123456`；
- `ADMIN_INITIAL_PASSWORD` 或一次性随机密码；
- 首次登录强制改密；
- 密码不反复写日志；
- 部署验证默认密码已失效。

### 6.4 SQLite

- `DB_PATH` 正式配置化；
- 每个连接 `foreign_keys=ON`；
- 启动和测试断言；
- `foreign_key_check`；
- 数据库备份/恢复演练。

### 6.5 业务基线

- member 创建时 owner 规则；
- owner 目标用户存在/启用校验；
- 批量转移逐条审计；
- 跟进编辑/删除后的派生时间重算；
- 手工 next_follow_at 的保留规则；
- 前端“邮件”与后端枚举统一；
- 明确现有宽松读取权限，不让 AI 继承。

### 退出条件

- 安全阻塞项有自动化回归；
- 生产部署确认；
- 数据备份可恢复；
- 派生时间在新增、编辑、删除场景一致。

## 8. 阶段 6：AI 和新模块权限边界

### 工作内容

- member 强制 owner 校验；

## 9. 阶段 7：通知队列、规则、幂等和 dry-run

### 工作内容

- `notification_rules`；
- `notification_logs` outbox；
- worker lease、重试、限流；
- 幂等键；
- cancelled/suppressed；
- 事件版本二次检查；
- 管理规则 API；
- 规则 preview；
- 日级 scheduler；
- 监控和告警；
- 所有规则默认关闭。

### Dry-run

至少运行一个完整业务周期：

- 只计算命中；
- 不调用微信；
- 检查数量、接收人和样例；
- 检查重复扫描；
- 检查已结束/已修改客户被抑制；
- 与人工 SQL 抽样对账。

### 退出条件

- 重复扫描无重复事件；
- 外部失败不影响业务；
- 可停止 worker 而不丢任务；
- dry-run 结果经业务确认。

## 11. 阶段 9：负责人变更提醒试点

这是第一个业务通知试点，范围最小、触发最明确。

### 工作内容

- 单条编辑走统一服务；
- 批量转移逐条处理；
- 公海认领走同一服务但默认 suppressed；
- 条件 `old != new AND new != actor`；
- 只通知新负责人；
- 消息脱敏；
- 详情链接二次鉴权；
- 小范围用户/客户白名单。

### 退出条件

- admin/member 转给别人都正确通知；
- 转给自己、公海自领、重复 owner 不通知；
- 批量真实变化数量与通知一致；
- 不出现重复或敏感字段。

## 12. 阶段 10：拜访计划和提醒

### 工作内容

- `visit_plans` 迁移；
- 列表、创建、修改、完成、取消；
- member owner 权限；
- 前一天、当天、开始前 N 分钟；
- revision 失效；
- 完成后由用户决定是否写历史跟进。

### 退出条件

- 修改/取消/完成后旧提醒不发送；
- 时区和跨日边界测试通过；
- 不能为他人客户建计划；
- 不把计划误当历史拜访。

## 13. 阶段 11：约定跟进逾期提醒

### 前置

- `last_follow_at/next_follow_at` 一致性已修复；
- 按日期而非小时；
- 暂搁置规则已确认；
- dry-run 对账完成。

### 工作内容

- due_today、overdue_1d/2d/3d+ 可配置；
- 结束状态停止；
- 新跟进、改日期、清空日期取消旧任务；
- 负责人变化重新解析接收人；
- 指定管理员升级，不强制 supervisor_id；
- `inactive_lead` 继续关闭。

### 退出条件

- 日期边界和节假日策略正确；
- 不把长期无活动混入；
- 同一 due_date/level/recipient 只发一次；
- 纯站内与微信结果可核对。

## 14. 阶段 12：现有关键状态提醒

### 工作内容

- 只使用现有 status；
- 真实变化事件；
- 默认少量开启；

- 避免跟进接口与线索编辑重复发。

### 退出条件

- 非重点状态不发；
- 不存在新销售阶段依赖；

## 17. 阶段 15：AI 日报、周报

### 工作内容

- 输入只使用确定性 SQL 结果和受控摘要；
- AI 生成文字总结；

- 周报增加推进、问题和建议，但不评分客户价值。

### 退出条件

- 失败降级演练通过；
- member 无公司级数据；
- 重复生成和发送幂等。

## 18. 阶段 16：安全、压力、回滚和生产放量

### 18.1 安全

- JWT 降权/停用；
- IDOR 和伪造 owner；
- 微信绑定冒用；
- adapter 签名和重放；
- Prompt 注入；
- 日志脱敏；
- secret 扫描；
- 上传和详情链接权限；
- 管理员 AI 也无系统工具。

### 18.2 稳定性与压力

- SQLite 写锁和 worker 并发；
- 批量转移 100 条；
- scheduler 大量命中；
- 渠道超时、429、5xx；
- adapter 掉线；
- iLink window/context 失效；
- Windows RPA 卡死；
- DeepSeek 超时和限流；
- 重启后任务恢复；
- 重复消息率。

### 18.3 回滚

- 关闭规则；
- 停 worker；
- 停普通微信适配器；
- 切企业微信或仅站内；
- 应用版本回滚；
- 数据库恢复演练；
- 保留新表而不继续消费；
- 不删除原业务数据。

### 18.4 放量

```text
开发环境
→ 隔离 PoC
→ dry-run
→ 1~2 名试点
→ 单一 owner_changed
→ 拜访
→ 约定逾期
→ 日报
→ AI
→ 分批扩大
```

每一步有观察期和回退开关。

## 19. 验收总清单

### 通知

- 普通新增线索不通知；
- 普通编辑不通知；
- 真实负责人变更才通知；
- 新负责人等于 actor 不通知；
- 公海自领不通知；
- 批量逐条审计和幂等；
- 约定逾期基于 next_follow_at 且按天；
- 长期未跟进独立、默认关闭；
- 拜访旧提醒失效；
- status 只用现有枚举；
- 外部失败不回滚业务。

### 微信

- 普通微信为目标；
- 普通微信方案经过独立 PoC；
- iLink 主动发送窗口已实测；
- 个人号自动化风险已接受才可使用；
- 企业微信可降级；
- secret/二维码/密码不进业务数据库、日志或前端。

### AI

- member 只能分析自己客户；
- 前端不能提交可信客户上下文；
- 后端重新查数；
- 无客户价值评分；
- 无数据库写、Shell、文件或管理工具；
- 日报数字由 SQL；
- 审计脱敏、截断、限权、可过期清理。

### 基线

- 数据库实时角色；
- 固定默认管理员密码已移除并部署验证；
- DB_PATH 和实际生产库明确；
- 每连接外键开启；
- foreign_key_check；
- 跟进派生时间一致；
- “邮件”枚举统一；

## 20. 风险登记

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| iLink 不能满足任意时刻主动推送 | 普通微信通知不完整 | PoC 验证；企业微信降级 |
| RPA/Hook 掉线或封号 | 通道长期不可用 | 不用主号；专机专号；不通过则排除 |
| 社区项目停止维护 | 客户端升级后失效 | 适配层隔离；候选复查；可切换 |
| 未提交修复被误认为线上 | 安全漏洞继续存在 | 核验 commit、评审、发布验证 |
| SQLite 派生日期错误 | 逾期误报 | 基线修复、dry-run、抽样对账 |
| member 当前读权限较宽 | AI 越权 | AI 独立 owner 授权，不继承页面 |
| AI 泄露敏感信息 | 安全事件 | 最小上下文、脱敏、无工具、审计 |
| 通知重复 | 干扰负责人 | unique dedupe、状态机、发送前二次检查 |
| AI 报告改写数字 | 管理误判 | SQL 数字独立，AI 只写文字 |
