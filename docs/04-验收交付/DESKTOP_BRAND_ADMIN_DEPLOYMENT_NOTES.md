# PC 管理后台与品牌数据域部署说明

## 部署前

1. 确认生产 `DB_PATH` 指向仓库外绝对路径。
2. 执行 `bash scripts/backup.sh`，核对备份文件可读取。
3. 在数据库副本上运行新版本，确认主迁移、品牌域初始化和外键检查均通过。
4. 完成后端构建、测试和 H5 生产构建。

## 构建

```bash
cd server
npm ci
npm run build
npm test

cd ../app
npm ci
npm run build:h5
```

## 发布

沿用现有部署流程。后端启动顺序为：

1. 校验配置开关
2. 运行原有主库迁移
3. 幂等初始化品牌数据域
4. 执行品牌域外键检查
5. 初始化管理员
6. 注册 HTTP 服务与桌面 H5 静态产物

## 数据变化

首次启动会新增品牌域表和 `brand_schema_meta`，不会删除、重建或改写原线索表。`leads.company_name` 保持不变。

## 回滚

应用回滚到旧版本时：

- 旧版本会忽略品牌域新增表。
- 原线索、用户、跟进、通知和备忘录数据仍可使用。
- 不应在普通回滚中删除品牌域表，以免丢失已经录入的数据。
- 如必须彻底撤销新增表，应先保留完整数据库备份，在维护窗口内按外键逆序执行离线清理。

## 观察项

发布后重点观察：

- 启动日志中的数据库初始化和外键检查
- 品牌/工商导入错误率
- 线索详情和列表查询时延
- SQLite busy/lock 错误
- 上传、导出和 H5 静态资源响应
