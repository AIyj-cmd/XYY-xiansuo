# 阶段六生产回滚运行手册

状态：仅在获授权的生产变更窗口使用。目标是先止损、保全数据与证据，再回退制品；禁止删除业务数据、通知历史、审计记录、迁移记录或执行破坏性 down migration。

## 1. 触发条件

- 迁移 checksum、完整性或外键校验失败；
- 实际 Nginx/PM2/H5/API 冒烟失败；
- 意外启动 Worker、Scheduler、AI、Mock 或任一真实外部渠道；
- 鉴权、数据隔离或静态制品严重异常；
- 发现备份、恢复或旧制品兼容性证据不完整。

## 2. 立即隔离

1. 停止继续发布和任何新增写入操作；保留日志、制品标识、时间线与脱敏诊断证据。
2. 确认并保持部署运行手册所列十项精确开关均为 `false`：通知捕获、Worker、通知 Scheduler、Mock、DeepSeek、三个 AI job、公海认领及 VITE 公海认领。
3. 若任何非 API 进程已启动，先停止 xiansuo Worker、AI Scheduler、Gateway 及全部消息渠道进程；不得操作其他项目 PM2 进程。
4. 不发送、重放或补发通知；不登录微信、不调用 DeepSeek、不处理真实凭证。

## 3. 数据库与制品回退

1. 对故障时点数据库做经批准的一致性保全备份；不写入、不清理原库，也不手工修改 `schema_migrations`。
2. 如果迁移未完成，保持新制品停止并记录失败；迁移事务应自行回滚。不得伪造迁移记录绕过失败。
3. 如果已迁移且需回退应用，只回退 API/H5/PM2 制品到已验证上一版；数据库保持 `001–006` 的前向兼容状态，不做 down migration。
4. 只有当生产数据库已不可用且获明确恢复授权时，才从迁移前一致性备份恢复到已确认恢复位置；恢复后执行完整性、外键、登录、只读 API、HTTPS/H5 冒烟。
5. 旧制品仅在已完成兼容演练时可启用；否则保持服务停止并升级决策。

## 4. 回滚完成标准

- API、HTTPS 反代、H5、登录和只读业务路径恢复；
- Worker、Scheduler、AI、Mock 与全部真实渠道未运行，相关开关均关闭；
- 数据库 `PRAGMA integrity_check=ok`、`PRAGMA foreign_key_check` 为空，迁移账本未被篡改；
- 无客户数据、密钥或完整生产路径进入工单/文档；
- 记录实际回退制品、备份证据、验证结果和后续修复门禁。

若无法同时满足这些标准，保持 NO-GO，不恢复流量。
